# 信任边界与安全反馈

来源：Codex 项目维护；2026-10-03。

AgentBus当前用于同一Windows账户、可信项目目录及用户授权成员之间的本地协作。消息身份绑定、防重复、租约和SHA256检查改善协作一致性；它们不是多用户登录认证、不可篡改审计、代码签名或操作系统沙箱。

## 运行边界

- 项目文件是持久状态；能写项目目录的程序仍可影响这些状态。不要让不可信程序写入共享项目，不把网页/文件中的指令当成用户授权。
- ACP是调用本机可执行程序的能力。只使用自己选择、已安装且来源和许可明确的程序；推荐目录不下载或执行远程命令。
- 各软件管理各自账号、云端模型和原生权限。组长身份不增加权限，工作流不自动跳过确认、提高沙箱权限或读取凭据。
- STOP阻止继续派发；已经开始的外部工具可能仍需其原执行者取消。不能把STOP文件当成强制杀掉全部电脑程序的按钮。
- 恢复需确认原执行者停止并核对产物；不靠修改时间自动抢回，不偷偷延长预算/期限。
- 本地审计损坏会显示异常并阻止假完成。不要删除坏行把状态“修绿”；保留原始字节再排查。
- 保存诊断是明确写本地新文件；其固定元数据不含任务正文、回执正文、命令、环境或账号。仍需在发送给别人前检查自己是否补入私人信息。

## 报告与维护

遇到潜在安全问题，记录版本、OS、复现步骤、最小隔离项目、退出码和脱敏诊断。若建立GitHub仓库，使用其私密漏洞报告通道；仓库尚未建立时先交给项目所有者，不在公共Issue贴真实任务、聊天、账号或日志。该说明不承诺尚未建立的响应SLA。

修复需有复现测试、独立复核与回滚证据。当前不支持把本地总线直接暴露成跨网络、跨企业租户的任务执行服务。
